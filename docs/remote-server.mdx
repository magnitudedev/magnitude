---
title: "Remote server"
description: "Run models on a dedicated machine and use them from another computer."
---

Use a machine such as a Mac Studio, a DGX Spark or a Linux box with a GPU for inference while your agent runs on your laptop. The server needs to be reachable from your laptop, through your local network or a private network such as Tailscale.

On the server, install the CLI only, turn on network access, and run `magnitude serve`, by hand or as a background service that starts at login or at boot.

## Install on the server

<Tabs>
<Tab title="macOS / Linux">
```sh
curl -fsSL https://magnitude.dev/install.sh | sh
```
</Tab>
<Tab title="Windows PowerShell">
```powershell
irm https://magnitude.dev/install.ps1 | iex
```
</Tab>
</Tabs>

This installs only the CLI, without the desktop app and without a graphical session. It installs into your own home folder (`~/.magnitude/cli`, or `%USERPROFILE%\.magnitude\cli` on Windows), so it needs no `sudo` or administrator rights. The `magnitude` command is `~/.magnitude/bin/magnitude` on macOS and Linux, and `%LOCALAPPDATA%\Programs\Magnitude CLI\magnitude.exe` on Windows. Open a new terminal or SSH session to use it.

If the server also has the desktop app, you already have the CLI; skip this step.

To run the server in a container instead, see [Docker](/installation/docker).

## Turn on network access

Create a long, random key:

<Tabs>
<Tab title="macOS / Linux">
```sh
openssl rand -hex 32
```
</Tab>
<Tab title="Windows PowerShell">
```powershell
$b = New-Object byte[] 32; [Security.Cryptography.RandomNumberGenerator]::Create().GetBytes($b); ($b | % { $_.ToString("x2") }) -join ""
```
</Tab>
</Tabs>

Add a `network` object with it to `~/.magnitude/config.json` (`%USERPROFILE%\.magnitude\config.json` on Windows), creating the file if needed and keeping any other fields:

```json
{
  "network": {
    "enabled": true,
    "apiKey": "YOUR_LONG_RANDOM_KEY"
  }
}
```

This serves every network the server is on. To serve only one, such as Tailscale, add `"bind"` with the server's address on it. See [Network access](/api/network-access) for addresses, hostnames and an SSH tunnel that needs no key, and [Configuration file](/reference/configuration-file) for every field.

If the server runs a firewall, allow inbound TCP port `10100`: for example `sudo ufw allow 10100/tcp`, or `sudo firewall-cmd --permanent --add-port=10100/tcp && sudo firewall-cmd --reload`. On Windows, see [Windows](#windows).

## Serve

```sh
magnitude serve
```

It serves until you press Ctrl+C. Check on it from another terminal:

```sh
magnitude status
```

It shows each address other devices can use, without the key.

## Keep it running in the background

To serve after you disconnect and after a restart, register `magnitude serve` with the system's service manager. Every definition below runs the `magnitude` command, never a versioned path inside `~/.magnitude/cli`, so it keeps working after updates. Set up only one per machine.

<Tabs>
<Tab title="macOS">
**At login.** A LaunchAgent runs `serve` while you're logged in at the Mac:

```sh
mkdir -p ~/Library/LaunchAgents ~/.magnitude/logs
cat > ~/Library/LaunchAgents/dev.magnitude.serve.plist <<EOF
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE plist PUBLIC "-//Apple//DTD PLIST 1.0//EN" "http://www.apple.com/DTDs/PropertyList-1.0.dtd">
<plist version="1.0">
<dict>
  <key>Label</key><string>dev.magnitude.serve</string>
  <key>ProgramArguments</key>
  <array><string>$HOME/.magnitude/bin/magnitude</string><string>serve</string></array>
  <key>RunAtLoad</key><true/>
  <key>KeepAlive</key><true/>
  <key>ProcessType</key><string>Interactive</string>
  <key>StandardOutPath</key><string>$HOME/.magnitude/logs/serve.log</string>
  <key>StandardErrorPath</key><string>$HOME/.magnitude/logs/serve.log</string>
</dict>
</plist>
EOF
launchctl bootstrap gui/$(id -u) ~/Library/LaunchAgents/dev.magnitude.serve.plist
```

To stop and remove it:

```sh
launchctl bootout gui/$(id -u)/dev.magnitude.serve
rm ~/Library/LaunchAgents/dev.magnitude.serve.plist
```

**At boot, before anyone logs in.** On a headless Mac, use a LaunchDaemon instead. It still runs as you, with your `~/.magnitude`. Run these as yourself, not in a root shell:

```sh
mkdir -p ~/.magnitude/logs
sudo tee /Library/LaunchDaemons/dev.magnitude.serve.plist > /dev/null <<EOF
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE plist PUBLIC "-//Apple//DTD PLIST 1.0//EN" "http://www.apple.com/DTDs/PropertyList-1.0.dtd">
<plist version="1.0">
<dict>
  <key>Label</key><string>dev.magnitude.serve</string>
  <key>ProgramArguments</key>
  <array><string>$HOME/.magnitude/bin/magnitude</string><string>serve</string></array>
  <key>UserName</key><string>$(id -un)</string>
  <key>EnvironmentVariables</key>
  <dict>
    <key>HOME</key><string>$HOME</string>
    <key>PATH</key><string>/usr/bin:/bin:/usr/sbin:/sbin</string>
  </dict>
  <key>WorkingDirectory</key><string>$HOME</string>
  <key>RunAtLoad</key><true/>
  <key>KeepAlive</key><true/>
  <key>ProcessType</key><string>Interactive</string>
  <key>StandardOutPath</key><string>$HOME/.magnitude/logs/serve.log</string>
  <key>StandardErrorPath</key><string>$HOME/.magnitude/logs/serve.log</string>
</dict>
</plist>
EOF
sudo chown root:wheel /Library/LaunchDaemons/dev.magnitude.serve.plist
sudo chmod 644 /Library/LaunchDaemons/dev.magnitude.serve.plist
sudo launchctl bootstrap system /Library/LaunchDaemons/dev.magnitude.serve.plist
```

With FileVault on, nothing starts after a restart until someone unlocks the disk. To stop and remove it:

```sh
sudo launchctl bootout system/dev.magnitude.serve
sudo rm /Library/LaunchDaemons/dev.magnitude.serve.plist
```

Logs: `~/.magnitude/logs/serve.log` and `~/.magnitude/logs/service.log`
</Tab>
<Tab title="Linux">
A systemd user unit runs `serve` as you:

```sh
mkdir -p ~/.config/systemd/user
cat > ~/.config/systemd/user/magnitude.service <<'EOF'
[Unit]
Description=Magnitude

[Service]
ExecStart=%h/.magnitude/bin/magnitude serve
Restart=always
RestartSec=10

[Install]
WantedBy=default.target
EOF
systemctl --user daemon-reload && systemctl --user enable --now magnitude
```

This starts it now and whenever you log in. To start it at boot and keep it running when you're not logged in:

```sh
sudo loginctl enable-linger $USER
```

Logs: `journalctl --user -u magnitude`

To stop and remove it:

```sh
systemctl --user disable --now magnitude
rm ~/.config/systemd/user/magnitude.service
systemctl --user daemon-reload
```
</Tab>
<Tab title="Windows">
**At sign-in.** In your own PowerShell, register a scheduled task:

```powershell
$action = New-ScheduledTaskAction -Execute "$env:LOCALAPPDATA\Programs\Magnitude CLI\magnitude.exe" -Argument "serve"
$trigger = New-ScheduledTaskTrigger -AtLogOn -User $env:USERNAME
$settings = New-ScheduledTaskSettingsSet -ExecutionTimeLimit ([TimeSpan]::Zero) -RestartCount 999 -RestartInterval (New-TimeSpan -Minutes 1) -AllowStartIfOnBatteries -DontStopIfGoingOnBatteries -StartWhenAvailable
$principal = New-ScheduledTaskPrincipal -UserId $env:USERNAME -LogonType Interactive -RunLevel Limited
Register-ScheduledTask -TaskName "Magnitude" -Action $action -Trigger $trigger -Settings $settings -Principal $principal
Start-ScheduledTask -TaskName "Magnitude"
```

It runs in your session with a console window; closing the window stops serving until you sign in again.

**At startup, before anyone signs in.** On a machine such as Windows Server, register it at startup from an administrator PowerShell, for the account that installed Magnitude:

```powershell
$account = "$env:COMPUTERNAME\alice"
$userProfile = "C:\Users\alice"
# A task that runs before sign-in logs on as a batch job; Performance Log Users holds that right by default.
Add-LocalGroupMember -Group "Performance Log Users" -Member $account -ErrorAction SilentlyContinue
$action = New-ScheduledTaskAction -Execute "$userProfile\AppData\Local\Programs\Magnitude CLI\magnitude.exe" -Argument "serve"
$trigger = New-ScheduledTaskTrigger -AtStartup
$settings = New-ScheduledTaskSettingsSet -ExecutionTimeLimit ([TimeSpan]::Zero) -RestartCount 999 -RestartInterval (New-TimeSpan -Minutes 1) -AllowStartIfOnBatteries -DontStopIfGoingOnBatteries -StartWhenAvailable
$password = (Get-Credential $account).GetNetworkCredential().Password
Register-ScheduledTask -TaskName "Magnitude" -Action $action -Trigger $trigger -Settings $settings -User $account -Password $password -RunLevel Limited
Start-ScheduledTask -TaskName "Magnitude"
```

Windows runs a task as another account before anyone signs in only with that account's password, so the task keeps it (entered in a prompt, never on the command line). A standard account also needs the right to log on as a batch job, which the group above grants; you can instead grant "Log on as a batch job" in Local Security Policy. Register the task again after the account's password changes.

Logs: `%USERPROFILE%\.magnitude\logs\service.log`

To stop and remove it (from an administrator PowerShell for the startup task):

```powershell
Stop-ScheduledTask -TaskName "Magnitude"
Unregister-ScheduledTask -TaskName "Magnitude" -Confirm:$false
```
</Tab>
</Tabs>

## Download a model

On the server:

```sh
magnitude hardware
magnitude models recommend --limit 5
magnitude models pull "MODEL_ID"
magnitude models show "MODEL_ID"
```

If recommendations are not ready, run `magnitude models list` to check assessment progress, then request recommendations again. Magnitude loads the model on the first inference request. To load it ahead of time, run `magnitude models load "MODEL_ID"`.

Or do all of this from the browser app on your laptop.

## Use the app from your laptop

Open `http://SERVER_IP:10100` in a browser on your laptop and sign in with the network access key. From there you can browse recommendations, download and load models, watch usage, and change settings. See [Open the app from another device](/api/network-access#open-the-app-from-another-device).

## Connect from your laptop

Use these settings in your agent or app:

| Setting | Value |
| --- | --- |
| OpenAI-compatible base URL | `http://SERVER_IP:10100/inference/v1` |
| API key | The network access key |
| Model | The exact model ID you downloaded |

Use your agent's [configuration instructions](/api/network-access#configure-the-app-or-agent), then [check the connection](/api/network-access#check-the-connection) from your laptop.

To use an agent on the server itself, connect it from your own terminal there:

```sh
magnitude connections connect pi
```

This writes the agent's configuration into your home folder, pointing at the server on `localhost`.

## Updates

While `magnitude serve` runs, it checks for updates, downloads them, and installs them when no inference request is running, then restarts in place. Clients reconnect after a short pause, and a background service keeps running through the update. If a new version fails, it is held back and the current one keeps serving.

To turn off automatic downloads, set `"autoDownloadUpdates": false` in `~/.magnitude/config.json`. `serve` then prints that an update is available, and `magnitude update install` installs it.

## The desktop app on the same machine

The desktop app always takes priority. While it is open, it serves, and `magnitude serve`, by hand or as a background service, waits and prints that another Magnitude app is serving. When you quit the app, `serve` resumes by itself.

Installing the desktop app, from [Download](https://magnitude.dev/download) or with `--desktop` (`-Desktop` on Windows), replaces the CLI-only install. Your models and settings stay. A background service keeps working on every OS, because it runs the `magnitude` command, which becomes the app's CLI. On Linux, `~/.magnitude/bin/magnitude` points at the package's `/usr/bin/magnitude` once the app has been opened.

## Remove the CLI-only install

1. Stop and remove the background service, if you set one up, with the commands under [Keep it running in the background](#keep-it-running-in-the-background).
2. Delete the CLI:

<Tabs>
<Tab title="macOS / Linux">
```sh
rm -rf ~/.magnitude/cli ~/.magnitude/bin/magnitude && rmdir ~/.magnitude/bin 2>/dev/null
for f in ~/.zprofile ~/.zshrc ~/.bash_profile ~/.bash_login ~/.profile ~/.bashrc ~/.config/fish/config.fish; do
  [ -f "$f" ] && sed -i.bak '/# >>> Magnitude CLI PATH >>>/,/# <<< Magnitude CLI PATH <<</d' "$f"
done
```

The loop removes the PATH block the installer added to your shell startup files, keeping a `.bak` copy of each file it changes.
</Tab>
<Tab title="Windows PowerShell">
```powershell
$dir = "$env:LOCALAPPDATA\Programs\Magnitude CLI"
Remove-Item -Recurse -Force $dir, "$env:USERPROFILE\.magnitude\cli"
# Edit the registry value directly so it keeps its type and unexpanded entries such as %USERPROFILE%.
$key = [Microsoft.Win32.Registry]::CurrentUser.OpenSubKey("Environment", $true)
$kind = $key.GetValueKind("Path")
$path = $key.GetValue("Path", "", "DoNotExpandEnvironmentNames") -split ";" |
  Where-Object { $_ -and [Environment]::ExpandEnvironmentVariables($_).TrimEnd("\") -ne $dir }
$key.SetValue("Path", ($path -join ";"), $kind)
$key.Close()
```
</Tab>
</Tabs>

Your models, settings and keys stay in `~/.magnitude` (`%USERPROFILE%\.magnitude` on Windows). Delete that folder too if you don't want them.

## Windows

If other computers need to reach the server, allow inbound TCP port 10100 in Windows Defender Firewall from an administrator PowerShell:

```powershell
New-NetFirewallRule -DisplayName "Magnitude" -Direction Inbound -Protocol TCP -LocalPort 10100 -Action Allow -Profile Private
```

This allows connections on networks Windows treats as private. If the server's network is set to Public, change its profile to Private in Settings, or use `-Profile Private,Public` only if you trust that network.

## Servers set up by earlier versions

- **Linux:** a server set up as a system service by an earlier version keeps working after it updates itself, with the same address, port and key. It runs as `magnitude.service` under the `magnitude` account, with its data and configuration in `/var/lib/magnitude/.magnitude/`. Logs: `journalctl -u magnitude`.
- **macOS:** a server set up by an earlier version runs as the `dev.magnitude.server` LaunchDaemon and keeps working. To remove it: `sudo launchctl bootout system/dev.magnitude.server && sudo rm /Library/LaunchDaemons/dev.magnitude.server.plist`.
- **Windows:** a `magnitude serve` service wrapped with NSSM keeps working.
