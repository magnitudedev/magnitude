---
title: Troubleshooting
description: "Resolve service, connection, download, and model problems"
icon: wrench
---

Start with **Status** in the desktop app. It reports the service, model, downloads, and tray separately. Agents can inspect the same system with `magnitude service status`, `magnitude models status`, and `magnitude connections list`; `magnitude docs cli` describes the headless commands.

## Setup did not finish

Reopen Magnitude and continue in Discover. Completed downloads remain available in My Models. Onboarding lives in the desktop application.

If the CLI reports that the desktop is missing, install the desktop application for your platform. Reinstalling the npm CLI alone does not install the desktop or its service.

## Service is unavailable

Open Status and read the failure. Use **Retry service** when offered. A service failure does not imply that a downloaded model was deleted.

```sh
magnitude service status
magnitude service start
```

Start requests run the desktop in the background. Use `magnitude app open` to show its window. If Status reports **Cleanup needs attention**, resolve that failure before attempting replacement processes; do not start a separate daemon manually.

## Harness cannot use Magnitude

Check Connections. Its status reflects the managed configuration on disk; external edits can disconnect an integration. Connect again to repair it, or use:

```sh
magnitude connections list
magnitude connections sync
```

Connect writes the configuration and supported integration files without launching the harness. Restart or reload the harness yourself when its configuration requires it.

Codex and Claude Code use Magnitude's local gateway while connected, including for hosted models. Keep Magnitude running, or remove the connection and restart the harness:

```sh
magnitude connections remove codex
# or
magnitude connections remove claude-code
```

## Model download failed

Check network access and free disk space, then retry from Discover or My Models. Magnitude can resume partial downloads when the source permits. Use the curated catalog in the app to select another model.

## Model will not load or was stopped

A downloaded model occupies disk space; a loaded model also needs inference memory. Check the model's failure in My Models and the current state in Status. Other applications can reduce available memory after the fit assessment. Free memory or choose a smaller recommendation and try again.

Stopping a model preserves its downloaded files and keeps the service available. A later inference request can load the selected model again. Full **Quit Magnitude** stops the service and its inference processes.

## Tray or login startup is unavailable

Some Linux desktop environments do not expose a supported tray host. Status reports this explicitly. Reopen Magnitude through your applications menu or `magnitude app open`; quit through the application menu or `magnitude service stop`.

Use Settings to enable launch at login. The CLI equivalents are `magnitude service install` to enable it and start the background app, and `magnitude service uninstall` to disable it and quit. `magnitude service stop` preserves the login setting.

## Report a problem

Include the app version, operating system, service/model status, and the steps that failed. On Linux, include your desktop environment and whether the session uses X11 or Wayland. Remove prompts, project contents, private paths, and credentials from any logs you share.

Do not delete the complete `~/.magnitude` directory as a troubleshooting step; it contains models and configuration. Open a [GitHub issue](https://github.com/magnitudedev/magnitude/issues) or ask in [Discord](https://discord.gg/EHt48pPWdC).
