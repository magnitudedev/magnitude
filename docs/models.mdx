## Choose a recommendation

**Discover** assesses your hardware and shows up to five recommendations. Start with **Balanced**, or choose Fastest, Faster, Smarter, or Smartest to shift the speed–intelligence trade-off.

## Read the model details

| Detail | How to use it |
| --- | --- |
| Intelligence | Compare model capability using its benchmark index. The displayed percentage is an index score, not an accuracy percentage. |
| Speed | Compare estimated generation throughput on your machine. It is an estimate, not a benchmark of your current task. |
| Memory | Check expected runtime memory, which is different from download size. |
| Fidelity / quantization | Lower-bit variants generally use less memory and disk space; higher fidelity preserves more of the original model. |
| Context | Check how much conversation and working material the serving configuration can accommodate. |
| Capabilities | Check whether the model supports features your task needs, such as vision or tool use. |
| Speculation | See the speculative-decoding method prepared for the model. Magnitude handles its setup. |

Use **Details** for source, license, and configuration information. Model licenses are separate from Magnitude's license.

## Browse Catalog

**Catalog** lets you search beyond the recommendations, filter by compatibility, and sort models. A model appearing in Catalog does not guarantee it fits your machine. Read its compatibility information before downloading.

## Download and manage models

Click **Download** for the selected model. **My Models** shows downloaded models and acquisition progress; its search, filters, and sorting help you find them later.

- **Load model** puts a downloaded model into memory. Replacing a running model asks for confirmation.
- **Stop model** unloads it without deleting the download. A later request can load it again.
- **Remove** deletes the installed model files to recover disk space.

Downloading and loading are different steps. A downloaded model uses disk space even while stopped; a loaded model also uses inference memory. Magnitude loads a model on demand when an agent requests it and unloads it when idle or memory is tight, so the first response after a while takes longer. Supported models use speculative decoding (MTP, DFlash, DSpark, or LiLiCorr) and prompt caching automatically.

Models are stored in `~/.magnitude/models`. To use another folder, see [Settings](/settings#model-storage).

## Change your agent's model

Choose a downloaded Magnitude model in your agent's model selector. If it isn't listed, reconnect the agent from **Connections**, then reload or restart it as described in its [integration guide](/integrations/overview).

For terminal control, see [CLI reference](/reference).

## Usage

**Usage** shows local inference activity by model for **Today** or **All time**.

| Metric | Meaning |
| --- | --- |
| Input tokens | Prompt and conversation tokens, including cached input. |
| Cached input | Tokens reused from cache; a subset of input tokens. |
| Output tokens | Generated tokens. |
| Generation speed | Output tokens per second. |
| Time to first token | Time before the response starts. Loading and prompt processing can delay it even when generation is fast. |

### API-equivalent cost

**API-equivalent cost** estimates what your local inference workload would have cost if run on a comparable hosted inference provider (such as Anthropic, OpenAI, Google, DeepSeek, or hosted open-weight model endpoints).

#### Calculation formula

Cost is calculated deterministically from standard published token rates:

```
uncached_input = total_input - cached_input

api_equivalent_cost = (
    uncached_input * input_price
    + cached_input * cached_input_price
    + output_tokens * output_price
) / 1_000_000
```

All prices are denominated in currency per million tokens. Cached input tokens are strictly a subset of total input tokens and are never counted twice.

#### Cached input pricing and fallback policy

When a hosted provider publishes a prompt cache discount rate (such as Anthropic's prompt cache hit rate or OpenAI's cached input rate), that published cached rate is applied directly to cached input tokens.

If a provider does not offer or publish prompt cache discount rates, Magnitude applies a transparent fallback policy: cached input tokens are charged at the standard input token rate. Magnitude does not invent synthetic discounts.

#### Model equivalence and configuration

- **Explicit Mapping**: Supported open-weight models map to their official hosted counterparts (for example, DeepSeek R1 local distillation maps to hosted DeepSeek-R1, and Llama 3.3 70B maps to hosted Llama 3.3 70B Instruct).
- **Comparison Selection**: Users can compare their workload against any published hosted model (such as Claude 3.5 Sonnet, GPT-4o, DeepSeek-V3, or Gemini 1.5 Pro) using the model selector on the Usage dashboard.
- **Unmapped Models**: Custom fine-tunes or community models without an exact counterpart are marked as unmapped rather than assigned an arbitrary guess. Users can select an explicit comparison model to view cost estimates.
- **Pricing Assumptions**: Published provider rates, source references, and verification timestamps can be inspected directly in the dashboard by expanding **View pricing assumptions**.

#### Limitations and difference from net savings

API-equivalent cost is **not** actual expenditure or net savings.

API-equivalent cost only calculates what hosted providers would have billed for the equivalent token volume at their list prices. Actual financial savings require taking into account electricity, local hardware acquisition and depreciation, subscriptions, cloud credits, maintenance, and operational overhead.
